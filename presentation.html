Background & Motivation

The Congestion Dilemma: Bufferbloat vs. Underutilization

Traditional rule-based heuristics struggle with modern wireless and varying bandwidth links.

1. Limitations of Legacy Protocols (Cubic, Reno)

  • Drop-Driven: Assume packet loss is the primary signal of bottleneck capacity.
  • Severe Bufferbloat: Fill router queues until tail-drop occurs, inflating end-to-end RTT from tens of milliseconds to seconds.
  • Multiplicative Backoff: Halve window size upon random drops, collapsing throughput on stochastic wireless/5G links.

2. The Deep Reinforcement Learning Paradigm

  • Kleinrock Optimal Target: Operate at physical BDP (maximum throughput, minimum unloaded RTT).
  • Multi-Dimensional Perception: Rather than a single loss event, observe flight size ratios, RTT inflation, and queue trends simultaneously.
  • Asymmetric Actions: Learn to aggressively drain queues during sudden drops while smoothly holding steady-state capacity.

Environment Dynamics

Stochastic Bottleneck Markov Engine

Simulating real-world non-stationary channels with severe, unpredictable capacity jumps.

Dynamic Bottleneck Transitions

  • Random Capacity Sampling: Target BDP uniformly sampled in [15.0, 36.5] MSS.
  • Enforced Shift Magnitude: |Δ BDP| ≥ 6.5 MSS on every transition to test extreme adaptability.
  • Stochastic Duration: Each capacity level persists for 45 to 85 steps (4.5s to 8.5s) before transitioning.

Physical Queue & Latency Simulation

  • Adaptive Base RTT Tracking: Continuously estimates unloaded base RTT (~84.0 ms) using low-percentile filtering.
  • Virtual Queue Buildup: Excess packets injected when cWnd > BDP simulate queuing delay and immediate RTT spikes.
  • BBR Queue Ceiling: Set at +25% above Base RTT (~105 ms) as the bufferbloat guardrail.

Mathematical Formulation

State Space, Actions & Multi-Objective Reward

Formulated for sample-efficient convergence and aggressive bufferbloat penalization.

Observation Space (8D)

  • (cWnd / BDP) - 1.0
  • Log-scaled cWnd size
  • Pipe In-Flight segment ratio
  • Relative RTT inflation (RTT - RTT_base)/RTT_base
  • Step-to-step RTT trend gradient
  • TCP congestion state flags
  • Packet loss / timeout flag
  • Normalized target BDP

Action Space (7 Discrete)

  • 0: -4.0 MSS (Emergency Drain)
  • 1: -2.0 MSS (Moderate Backoff)
  • 2: -0.5 MSS (Fine Trim Down)
  • 3: 0.0 MSS (Sweet-Spot Hold)
  • 4: +0.5 MSS (Fine Trim Up)
  • 5: +2.0 MSS (Bandwidth Probe)
  • 6: +4.0 MSS (Fast Ramp-Up)

Reward Equation

R = R_bdp + R_progress
    - C_over - C_delay - C_loss

  • R_bdp: High reward near ±0.6 MSS.
  • C_delay: 4.0 × (excess_delay)^1.5.
  • C_over: Quadratic penalty on excessive expansion.
  • C_loss: -4.5 penalty upon drops.

Reproduction & Future Scope

Execution Guide & Research Horizons

How to Run

# 1. Clone & activate
git clone https://github.com/shetgaonkarshubh/tcp-rl-ns3.git
cd tcp-rl-ns3 && source venv/bin/activate

# 2. Build ns-3 with rl-tcp.cc
cp rl-tcp.cc ~/ns-allinone-3.40/ns-3.40/contrib/opengym/examples/rl-tcp/
cd ~/ns-allinone-3.40/ns-3.40 && ./ns3 build

# 3. Launch automated tmux pipeline
cd ~/tcp-rl-ns3 && ./run_pipeline_tmux.sh

# 4. Live interactive telemetry demo
./run_realtime_demo.sh
